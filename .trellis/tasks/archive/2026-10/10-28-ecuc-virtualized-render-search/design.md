# Design: ECUC virtualized rendering and search/filter engine

Read with `prd.md`. Reference (read-only, separate repo): `D:\workspace\vscode-hex-scope`'s
`src/webview/render/virtualScroll.ts` (cumulative heights, visible range/overscan, spacers),
`src/webview/memory/memoryGrid.ts` (windowed slice), and `src/core/search.ts` /
`src/webview/search/searchEngine.ts` (debounce, cancellation, progress, visible matches). Those are
flat-grid patterns; the ECUC tree, two presentations and editing contracts are ours.

## 1. Current flow and target flow

Current:

```text
ecucEditorProvider
  -> scanEcucValues(model)
  -> renderTree(model) -> 12k nested .node/.children HTML string
  -> renderHtml embeds the whole tree
  -> browser parses/layouts 12k rows + 12k line-number pseudo-elements
  -> filter scans/toggles every DOM item and highlights every match
  -> re-scan sends a new full tree HTML string
```

Target:

```text
ecucEditorProvider
  -> scanEcucValues(model)
  -> buildRows(model, lineIndex) -> compact row data (no row HTML)
  -> renderHtml embeds escaped row JSON + static shell
  -> page parses rows, flattens the visible/collapsed/filtered list
  -> virtual window renders viewport rows + overscan only
  -> scroll/filter/collapse changes recompute the window, not the whole tree
  -> re-scan sends row data; the page keeps state and re-renders the window
```

The host row builder is the only place that knows the ECUC ordering/display rules; the page is the
only place that knows windowing/filter UI. The row builder must not emit display HTML.

## 2. Row data

`src/editor/renderRows.ts` (new; pure, no `vscode`):

```ts
export interface MetaPart {
  cls: 'short' | 'variant' | 'hex' | 'context' | 'condition' | 'annotation';
  text: string;
  title: string;
}

export interface EcucRow {
  id: string;
  kind: 'module' | 'container' | 'parameter' | 'reference';
  level: number;              // 1-based
  parentId: string | null;
  subtreeSize: number;        // descendants in display order
  posinset: number;
  setsize: number;
  hasChildren: boolean;
  label: string;              // definition-ref tail or dotted module path
  shortName?: string;
  definitionRef: string;
  value?: string;             // raw value/target for copy/edit
  valueKind?: 'numeric' | 'textual' | 'boolean';
  shownValue?: string;        // quoted/display value
  target?: string;
  title: string;
  meta: MetaPart[];
  sourceLine: number;         // 1-based row line number
  line: number;               // 0-based inspector start
  column: number;
  endLine: number;
  endColumn: number;
  haystack: string;           // lower-cased label + short + value
}

export interface RowDocument {
  rows: EcucRow[];            // DFS/display order
  digits: number;             // source-line digit count
}
```

- Reuse `orderModules` / `orderContainers` / `orderMembers`, `lastShortName`, `dotted`, `camelize`
  and the current `suffixSpans` rules; replace HTML strings with `MetaPart`.
- `subtreeSize` is computed while walking (children are contiguous in DFS order). It is the only
  structural index the page needs for collapse; `parentId` is for filter ancestors.
- `sourceLine` is 1-based; `line` remains 0-based for the inspector, matching the existing contract.
- `haystack` is the current `filter.ts` `haystack` (label + short + raw value, lower-cased).
- The module prefix stays CSS (`::before`); `label` is the dotted path.
- The header (`schema`/`package`) remains a small static HTML block generated by `renderHtml`, because
  it is two or three lines and must align with the gutter.

## 3. Page embedding and re-scan

- `renderHtml` writes a static shell:
  - toolbar, `#notice`, `#content`, `#main`;
  - `.meta` header;
  - `#tree` with `role="tree"`, `aria-label`, `data-ln-digits`;
  - top/bottom virtual spacers and an empty window container inside `#tree`;
  - `#empty`;
  - details inspector.
- The initial rows are embedded as escaped JSON in `<script type="application/json" id="ecuc-rows"
  nonce="...">` (escape `<` to `\u003c` so model text cannot close the script). The page script reads
  `JSON.parse`; no model text is interpolated into executable JS or `innerHTML`.
- `ecucEditorProvider` re-scan sends `{ type: 'model', rows, digits, selectedId }` instead of
  `{ type: 'model', tree: renderTree(...) }`. The message type stays `model` because the value
  widget clears its edit state on it; the payload is row data. The page replaces the row store and
  rebuilds the visible/window state. The host still owns the model, ordering, ranges, selectedId and
  messages.
- The harness `scripts/preview-ecuc.js` uses the same `renderHtml` and `?view`/theme options; its
  `preview:check` assertion changes from the full `renderTree` string to the production row JSON +
  shell (and still verifies the production renderer is the source).

## 4. Flattening and collapse/filter

The page keeps `rows` in display order and derives a `DisplayRow[]`:

```ts
type DisplayRow =
  | { type: 'node'; row: EcucRow; rowIndex: number; depth: number; height: number }
  | { type: 'brace-open' | 'brace-close'; level: number; height: number };
```

- Walk rows by index. A row is skipped when it is inside a collapsed node's `subtreeSize`, unless a
  filter match is inside it (the current filter expands ancestors while active without touching the
  collapsed set). `parentId`/`subtreeSize` make this linear in the visible count, not DOM.
- Filter active: compute `visibleNode[i]` = row matches or any descendant matches. Only visible nodes
  and their ancestors are displayed; a matching container's unmatched children stay hidden, matching
  the current filter semantics. The collapsed state is overridden only for ancestors of matches; the
  saved collapsed set is untouched, so clearing restores it.
- Document adds a `brace-open` before an expanded node's visible descendants and `brace-close` after
  them; a collapsed node keeps its `{ … }` row stub and no child braces. Tree has no brace rows.
- The count is the displayed node count (matches + ancestors); `No matches` when no row matches; the
  empty state remains the source-comment line.
- The view toggle recomputes `DisplayRow[]` with the other view's heights; it preserves the selected
  row or the top visible row, not the raw scrollTop (the heights differ).

## 5. Virtual scroll

`src/editor/virtualScroll.ts` (new; pure, testable):

```ts
interface VirtualState {
  rowCount: number;
  rowHeight: (index: number) => number;
  containerHeight: number;
  scrollTop: number;       // content-relative, after header/tree offsets
  bufferSize: number;
}
calcVisibleRange(state): [start, end)  // cumulative heights + lowerBound, buffer/overscan
calcRowOffset(index, state)
calcTotalHeight(state)
```

- Heights:
  - Document node and brace rows: `--ecuc-lh` (one line).
  - Tree node rows: a deterministic height based on `meta.length` (two fixed variants, e.g.
    `--tree-row-h` / `--tree-row-h-meta`); `.row-meta` is one line with ellipsis so the height cannot
    drift. The page measures three hidden CSS probes once per view/data change (`measureHeights`), so
    the CSS stays the single source of height; no measurement depends on the window or a row.
  - No compressed/physical-scroll mapping: 12k rows are far below the 16M px cap; the ref's
    compressed mode is not copied.
- Layout:
  - `#main` remains the scroll container; `.meta` scrolls away at the top.
  - The virtual range uses the row-region offset (`#tree` top plus its padding), clamped; the page
    measures the probe heights once per view/data change (not per row), and row heights are
    deterministic.
  - `#tree` contains a top spacer, the window rows, and a bottom spacer (all aria-hidden), so total
    scroll height is stable.
  - `renderWindow(start, end)` builds only those rows via DOM APIs; it updates the spacers and the
    line-number width. If the range did not change, do nothing.
  - The scroll handler uses `requestAnimationFrame`; it computes the range and renders. A scroll that
    only changes scrollTop within the buffer/overscan does not re-render.
- Focus:
  - `focusRow(index)` ensures the index is in the window (scrolls into view if needed), renders,
    then sets the roving tabindex/focus.
  - After a window update, if the previous focus id is still rendered, restore focus to its new
    element. If it left the window, do not steal focus from the document; set the roving tabindex to
    the nearest visible row. Keyboard navigation always renders the target before focusing.
  - The selected/focused row's data is available in `rowById` even when offscreen; the inspector uses
    that, not DOM.
  - Mouse wheel scrolling while a tree row is focused may move focus to the nearest rendered row;
    this is a virtual-window consequence, recorded.

## 6. Row rendering

The page builds rows with `document.createElement` / `textContent` (never model `innerHTML`):

```text
.node[role=treeitem][aria-level/posinset/setsize/expanded/selected][data-node-id/data-kind]
  .row.k-<kind>.[has-value|no-value][data-line][data-level]
    twisty|spacer (SVG; Document gutter / Tree grid)
    .glyph (Tree only; inline SVG by kind)
    .label (module prefix via CSS; text)
    .punct '=' + .value(data-value-kind) + .value-text
    .row-meta (short/variant/hex/context/condition/annotation; text nodes)
```

- The row builder uses the row data and the existing CSS contracts. `.value` remains a direct child;
  the value widget's `:scope > .row > .value` and first-listener contract are unchanged.
- The line number is the existing `data-line` + `.row::before`; brace rows have no `data-line`.
- The Document full-row tint/rail uses the flat row's negative gutter margin plus a `data-level`
  padding (attribute CSS, not an inline style: the CSP blocks style attributes). The same pattern for
  the line-number/fold gutter. The row background covers the gutter.
- The Tree grid, chips/glyphs/dotted values and hidden twisty rules are reused; the Tree meta is a
  single line. The Document/Tree visual tokens and details styling are unchanged.
- The virtual row HTML is built per window; no thousands of DOM nodes. The current `GLYPHS`/twisty
  SVG strings move into the page builder or a shared inline constant; no asset files.

## 7. Search/filter engine

`src/editor/filter.ts` gets pure row functions:

```ts
interface FilterIndex { haystacks: string[]; }             // built once per row set/view
filterRows(rows, query): { matches: boolean[]; visible: boolean[]; matchCount: number }
matchRanges(text, query): MatchRange[]                    // existing
```

- The index is the row array's normalized `haystack` strings; no DOM, no inverted index. A 12k
  lower-case `includes` scan is a few milliseconds; the old cost was DOM toggling/highlighting, not
  the string scan.
- The page input handler debounces ~120 ms (matching the reference pattern), increments a generation
  token, runs the scan, discards stale results, then recomputes `DisplayRow[]`, count and empty state.
  The scan is synchronous for 12k; if profiling shows >16 ms, it can be chunked with a time budget
  without changing semantics. A Web Worker is out of scope (CSP/no dependency).
- Filtering does not touch hidden rows; only the window rows are rendered and highlighted.
  `matchRanges` highlights label, short name and `.value-text` on visible rows; the fields and
  substring semantics are unchanged.
- The input is cleared with Escape/clear; clearing restores the collapsed set and the previous
  window/scroll (the saved scroll may be clamped if the query changed the height).

## 8. State, interactions, inspector, editing

- Page state: `rows`, `rowIndexById`, `collapsed`, `selectedId`, `filterQuery`, `filterMatches`,
  `filterVisible`, `view`, `focusId`, `windowRange`, `scrollTop`. Details visibility stays in the
  existing `{ view, inspectorHidden }` state.
- Re-scan `setRows` preserves selected id, collapsed set, query, view and scroll where possible;
  prunes missing ids; re-renders the window. `prepareFocus` expands the ancestors of the
  host-selected id before deciding whether it is displayable, then scrolls it in; a `select` message
  refreshes the spacers before `focusRow` so a newly expanded total height can be reached.
- Click select, twisty toggle, double-click/Ctrl+Alt+Enter reveal, target follow, Enter/Space,
  Home/End, PageUp/PageDown, type-ahead, F2/value edit, Tab/Shift+Tab, copy and Escape are re-wired to
  the flat visible node list. `moveTarget`/`focusRow` use indices; no `querySelectorAll` over all
  rows.
- Inspector: `updateInspector` reads `rowById` + meta/source fields; selected offscreen rows still
  show. Actions copy/reveal/follow use the row data/id.
- Editing: the value widget still operates on a rendered `.value`; after a commit, the host re-scan
  sends rows and the page rebuilds. A selected row that is offscreen is scrolled/rendered before an
  edit/reveal/follow. A window rebuild with the edited row still visible detaches and reattaches the
  open input (text, pending/error and caret); if the row leaves the window the edit is dropped rather
  than left detached to commit a hidden value.
- The details panel, strip, tokens, line-number gutter and bottom sheet keep the previous task's CSS;
  only the row container/window and row builder change.

## 9. Accessibility

- The flat tree uses `role="tree"` with direct `role="treeitem"` children, `aria-level`,
  `aria-posinset`/`aria-setsize`, `aria-expanded`, `aria-selected`, and roving `tabindex`. This is a
  valid tree representation without `role="group"` wrappers; the old group assertions are updated.
- The virtual spacers are `role="presentation"`/`aria-hidden`; brace rows are decorative/aria-hidden.
- The focused/selected row is always rendered (focusRow/scroll). After a window update, focus is
  restored by id if it remains in the window; otherwise the roving tabindex moves to the nearest
  rendered row. Keyboard navigation renders the target before focusing.
- The accessibility tree exposes the window, not every offscreen row; screen readers navigate the
  rendered rows with the level/position metadata. This is a documented virtual-tree limitation, not
  presented as full-tree exposure.
- High contrast, focus rail, selected tint and reduced motion keep the previous rules; no
  color-only selection cue.

## 10. Verification and targets

- Pure tests: row generation/order/subtree metadata; visible-list collapse/filter/ancestor logic;
  virtual range/offset/total with fixed and two-height rows; filter match/visible/count; window
  start/end boundaries.
- Browser harness: `sample/display-rules`, `large`, `huge`, both views; load, filter, DOM row count,
  scroll windows, selection/focus, details/edit/empty; captures.
- Performance baseline (current Document, dark): large 717/823 ms, filter 55.7 ms; huge 3,838/3,855
  ms, filter 102.4 ms. Targets: large <=600 ms, huge <=1.5 s, filter <=30 ms; DOM treeitems <=200
  (viewport buffer), no blank gaps at normal scroll. Record the measured numbers; timings vary.
- Gates: `npm run check-types`, `npm run lint`, `npm test`, `npm run preview:check`; mutation table.
- A real VS Code webview still needs an Extension Development Host check for theme/font/focus/
  clipboard; the harness is page-side evidence.

## 11. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Row JSON is large / parse cost | Compact fields; measure; escape `<`; no HTML; initial parse target |
| Flat tree loses `role=group` semantics | Use level/posinset/setsize + focus row; document the window limitation; update a11y tests |
| Tree row heights drift | Deterministic two-height CSS + JS; one-line meta; tests |
| Focus lost on scroll/window update | Restore by id; roving tabindex to nearest; keyboard renders target |
| Filtering semantics change | Reuse `matchRanges`/haystack fields; match+ancestor tests; clearing restores collapsed state |
| Re-scan loses state | Row-id pruning; preserve selected/collapsed/query/view/scroll; ordered `postMessage` plus row reconciliation |
| Inspector reads offscreen DOM | Row data map, not nodes; tests |
| Open value edit detached by a window rebuild | Detach/reattach the input to the rebuilt row; drop it if the row leaves the window |
| CSP blocks inline style depth | `data-level` + attribute CSS; no style attributes |
| Performance target missed | Measure after each layer; no full DOM fallback; if needed chunk filter |
| Visual regression | Quiet-source/Tree captures, detail/selection tests |

## 13. Wrong vs correct

**Wrong - virtualize by hiding rows.**

```css
.node[data-offscreen] { display: none; }
```

The full DOM is still built and laid out once; the lag remains.

**Correct - render a window over a flat list.**

```ts
const [start, end] = calcVisibleRange(state);
renderWindow(start, end); // top/bottom spacers, viewport +/- overscan
```

**Wrong - filter the DOM.**

```ts
document.querySelectorAll('#tree [role="treeitem"]').forEach(/* toggle display */);
```

**Correct - filter the row index, then render the window.**

```ts
const { matches, visible } = filterRows(rows, query);
renderWindow(...visibleRows(rows, visible, collapsed));
```

**Wrong - build row text with `innerHTML`.**

```ts
row.innerHTML = model.label; // model text can contain markup
```

**Correct - build text nodes.**

```ts
label.textContent = row.label;
```

**Wrong - inline depth style under the CSP.**

```html
<div class="row" style="--depth: 3">
```

**Correct - attribute CSS.**

```css
.row[data-level="3"] { padding-left: calc(var(--gut) + var(--indent) * 2); }
```
