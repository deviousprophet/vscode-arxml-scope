# ECUC scanner and ARTEXT model (core)

Core deliverable of the parent task. Implements the parsing, ordering, resolution and validation
semantics for a single ECUC-Values arxml file. **Carries no `vscode` imports** (parent D16) so it can
later run under F0 or a standalone language server.

Parent requirement IDs (R1–R18), decisions (D1–D16) and the full rationale live in
`../10-14-ecuc-artext-editor/prd.md` and `../10-14-ecuc-artext-editor/design.md`.

## Goal

Turn one `.arxml` file's text into an ARTEXT information model in which every node carries the source
ranges needed for navigation and for editing, plus the ordering semantics of the legacy mapping.

## Prerequisites

None. This is the first child and the prerequisite for both others. Neither de-risking spike in the
parent plan is required for this work.

## Scope

- Single-pass scanner over a caller-supplied string. No file I/O: the text arrives from the caller, so
  this child never touches the filesystem, encoding or BOM handling (parent §5).
- The model, its types and ranges.
- The existing-element path index for same-file reference resolution (mechanism only; using it for
  navigation is the editor child's job).
- Ordering (`sort all` + the exception list), as pure functions.
- Value validation and XML escaping.
- Synthetic fixtures and expected models.

## Requirements

- Parse without building a DOM, in a single pass, using an iterative stack so nesting depth cannot
  overflow (parent R1, D7).
- Detect ECUC-Values content with a namespace-tolerant test, and reject non-`.arxml` inputs before any
  content is examined (parent R2).
- Every node carries the range of its source element, and, where it renders text, the range of that
  text: a parameter's value, an element's short name, a reference's target path (parent R3).
- Carry everything the legacy mapping conveys, including `SW-SYSCOND`, post-build-variant and
  annotation suffixes, and handle containers nested at least five levels deep (parent R4).
- Ordering exactly as `sort all` with the exception list, including declaration order for exception
  entries (parent R5, D11).
- Resolve a reference path to a target range when the target is in the same file, distinguishing
  exact, unique-suffix, ambiguous and absent (parent R6).
- Validate candidate values and escape them for XML, refusing anything that would corrupt the file
  (parent R13).
- Retain no reference to the input string in the returned model.

## Acceptance criteria

- [ ] AC1. The model from each synthetic fixture matches its committed expected model exactly,
      including a container nested six levels deep, all condition and annotation suffixes, CDATA text,
      entity references, and a self-closing `<VALUE/>`.
- [ ] AC2. `<VALUE>` is captured correctly in **both** of its contexts in a single fixture: as a
      parameter value and inside a `POST-BUILD-VARIANT-CONDITION`.
- [ ] AC3. A namespaced ECUC file (`<ns:ECUC-MODULE-CONFIGURATION-VALUES>`) is detected; a non-`.arxml`
      path is rejected without the content being consulted; an `.arxml` without ECUC values is rejected.
- [ ] AC4. Layout is irrelevant: the same model results from fixtures differing only in indentation,
      line endings, attribute order, and interleaved comments and processing instructions.
- [ ] AC5. `sort all` orders modules, containers, parameters and references by `DEFINITION-REF` then
      identity; entries whose `DEFINITION-REF` tail is in the exception list keep declaration order
      among themselves; parameters and references never interleave; a `DEFINITION-REF` that is a
      prefix of another orders as the legacy string key would.
- [ ] AC6. `declaration` mode returns the authored order for every list.
- [ ] AC7. Resolution returns the exact match when present, a unique suffix match otherwise, nothing
      for an ambiguous suffix, and nothing for an absent path.
- [ ] AC8. Validation accepts `true`, `false`, decimal integers, hexadecimal literals and decimal
      fractions with optional exponent; refuses other forms; refuses an unchanged value; and reports
      the escaped text to write for a value containing `&`, `<` or `>`.
- [ ] AC9. `npm run check-types`, `npm run lint` and `npm test` pass.

## Out of scope

- Any rendering, webview, editor or command. No `vscode` import may appear under `src/core/`.
- Reading or writing files; the caller supplies text and applies writes.
- Cross-file resolution, package merging and any workspace index (parent: F0/F2).
- The ARTEXT text form, its grammar, `Open as ARTEXT` and Compare (parent D4).

## Constraints

- No new runtime dependency; the scanner is hand-written (parent D7).
- Offsets are UTF-16 code units, matching how VS Code expresses positions.
- Expected models are authored from the rules in
  `../10-14-ecuc-artext-editor/research/legacy-artext-analysis.md`, never generated by the scanner
  under test.
- Fixtures are synthetic; no real customer file may be committed (parent D13, R17).
